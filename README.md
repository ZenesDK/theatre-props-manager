# Сервис учёта театрального реквизита (TheaterProps)

Консольное приложение для учёта, выдачи, бронирования
и инвентаризации театрального реквизита.

## Назначение

Информационная система предназначена для автоматизации учёта, контроля
перемещений и инвентаризации театрального реквизита, бутафории, костюмов
и декораций. Проект решает проблему хаоса на складах, исключает утерю
ценных предметов и оптимизирует процесс подготовки к спектаклям
и репетициям.

## Целевая аудитория

* **Заведующие постановочной частью (завпосты)** — контроль готовности
  материальной базы к спектаклям.
* **Заведующие складами и реквизиторы** — оперативный учёт, выдача
  и приёмка предметов.
* **Режиссёры и помощники режиссёров** — поиск и бронирование предметов
  под конкретные постановки.
* **Администрация театра** — инвентаризация и контроль имуществом.

## Основные сущности

* **Предмет реквизита (Prop)** — инвентарный номер, название, категория,
  состояние, статус (на складе / выдан / в ремонте / утерян / списан),
  локация.
* **Локация (Location)** — место хранения или использования (склад,
  сцена, репетиционный зал, мастерская).
* **Сотрудник (Employee)** — ФИО, должность, материальная ответственность.
* **Перемещение (Movement)** — запись о выдаче или возврате предмета:
  дата, ответственный, локация, цель.
* **Бронирование (Reservation)** — резервирование предмета на дату
  под постановку.
* **Спектакль (Production)** — на текущем этапе представляется строкой
  в бронировании; полноценная сущность будет введена при переходе к ООП.

## Возможности (версия ПР2)

* **Каталогизация:** добавление предметов с контролем уникальности
  инвентарного номера; просмотр с фильтрами по категории и статусу;
  поиск по подстроке названия или инв. номера; сортировка по названию,
  категории, состоянию, статусу.
* **Перемещения:** выдача реквизита сотруднику с указанием локации
  и цели; возврат с фиксацией состояния; журнал перемещений.
* **Бронирование:** проверка доступности предмета на дату; создание
  и отмена бронирований; запрет повторного бронирования на ту же дату.
* **Инвентаризация:** сверка наличия по локации; отметка ненайденных
  предметов как утерянных; отчёт в JSON.
* **Статистика:** распределения предметов по статусам, категориям
  и локациям.
* **Справочники:** управление локациями и сотрудниками.

## Формат хранения данных

Данные приложения хранятся в JSON-файлах каталога `data/`:
`props.json`, `locations.json`, `employees.json`, `movements.json`,
`reservations.json` — списки словарей с полем `id`. Даты хранятся
в ISO-формате (`ГГГГ-ММ-ДД`). Данные загружаются при запуске
и сохраняются сразу после каждого изменения. Отчёты инвентаризации
записываются в `reports/` с отметкой даты и времени в имени файла.

## Требования

* Python 3.10+;

pip install -r requirements.txt

flake8

## План развития

1. **Этап 1 (выполнен, ПР1–ПР2):** консольное приложение — учёт,
   перемещения, бронирование, инвентаризация, статистика.
2. **Этап 2 (ПР3):** переход к объектно-ориентированной модели:
   сущности проекта реализуются классами.
3. **Этап 3 (ПР5–ПР12):** веб-приложение на Django: страницы,
   база данных, пользователи, формы, REST API.
4. **Этап 4:** контейнеризация и настройка CI/CD.
